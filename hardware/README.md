# Аппаратный стенд XZT-IIoT: инструкция на первый день

Цель: настоящий Zero-Trust шлюз, который проверяет каждую команду от
ESP32 и пропускает её к насосу только после проверки. Решения принимает
**тот же движок политик**, что и в исследовательской части
(`self_hardening/`), но атрибуты теперь **измеряются**, а не
генерируются.

```
 ESP32 №1 датчик ──┐                         ┌──> ESP32 №2 насос + светодиоды
 ESP32 №3 «хакер» ─┼──> MQTT-брокер ──> ШЛЮЗ ─┘
                   │      (ноутбук)   (ноутбук, gateway.py)
       сеть: точка доступа телефона (отдельная, изолированная)
```

На первый день шлюзом будет ноутбук. Raspberry Pi подключим позже, код
тот же.

**Что взять в FabLab:** список в [`BOM.md`](BOM.md), там же что проверить
при получении деталей.

**Порядок:** сегодня вечером ставишь программы (раздел 0) и прогоняешь
всё в симуляторе (раздел 0.5). Завтра повторяешь ту же схему на
настоящих деталях (разделы 1–6).

---

## 0. Вечером дома (30–40 минут, без железа)

1. **Arduino IDE 2** (arduino.cc). Затем:
   *Файл → Настройки → Дополнительные ссылки для менеджера плат:*
   `https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json`
   *Инструменты → Плата → Менеджер плат →* найти **esp32 by Espressif**,
   установить. Если завтра скетч не соберётся на версии 3.x, поставь
   **2.0.17**: на 2.0.x код проверен компилятором.
   **Если платы ESP8266 (NodeMCU / Wemos D1 mini):** добавь ссылку
   `https://arduino.esp8266.com/stable/package_esp8266com_index.json`,
   установи **esp8266 by ESP8266 Community** (проверено на 3.1.2), плата
   **NodeMCU 1.0 (ESP-12E Module)**. Тот же скетч, выводы смотри в разделе 2b.
   Драйвер USB для этих плат: **CH340** (если порт не появляется).
2. *Скетч → Подключить библиотеку → Управлять библиотеками*, установить:
   **PubSubClient** (Nick O'Leary), **ArduinoJson** (Benoit Blanchon, v7),
   **OneWire**, **DallasTemperature**.
3. **Mosquitto** для Windows (mosquitto.org/download). При установке
   оставь всё по умолчанию. Путь обычно `C:\Program Files\mosquitto`.
4. В папке проекта:
   ```
   git pull
   python -m pip install paho-mqtt pyyaml
   python -m pytest hardware/gateway -q
   ```
   Должно быть `9 passed`.
5. Проверь USB-кабель: он должен **передавать данные**, а не только
   заряжать. Если плата не видна в *Инструменты → Порт*, нужен драйвер
   **CP210x** или **CH340** (смотри, какой чип стоит рядом с USB на плате).

## 0.5. Проверка в симуляторе Wokwi (сегодня, без железа)

[Wokwi](https://wokwi.com) бесплатно симулирует ESP32, датчик, реле,
светодиоды, кнопки и Wi-Fi. Симуляция работает на **той же прошивке**,
что пойдёт на платы.

1. Придумай свой префикс топиков, например `xzt-kirik-4821`, и в папке
   проекта выполни:
   ```
   python hardware/wokwi/make_wokwi.py --prefix xzt-kirik-4821
   ```
   Появятся три папки: `hardware/wokwi/sensor`, `actuator`, `attacker`.
2. На wokwi.com: **New Project → ESP32**. В редакторе замени содержимое
   `sketch.ino` и `diagram.json` содержимым из папки `sensor`. Добавь
   вкладку `libraries.txt` (стрелка рядом с вкладками → *New file*) и
   вставь туда содержимое одноимённого файла. Сохрани проект.
   То же самое сделай для `actuator` и `attacker`, каждый в своей
   вкладке браузера.
3. На ноутбуке запусти шлюз против того же публичного брокера:
   ```
   python hardware/gateway/gateway.py --broker broker.hivemq.com --prefix xzt-kirik-4821 --enroll
   ```
4. Запусти симуляцию датчика (зелёная кнопка ▶). Нажми в симуляторе
   кнопку **A pump ON**. В шлюзе появится `[enroll] ... ALLOW`. Перезапусти
   шлюз без `--enroll`.
5. Запусти симуляцию насоса во второй вкладке, снова нажми **A** у
   датчика: у насоса загорится зелёный светодиод и синий «PUMP»
   (вместо мотора в симуляторе стоит светодиод).
6. Запусти «хакера» и пройди сценарии из раздела 5.

Если в симуляторе всё сработало, значит прошивка, схема подключения и
шлюз правильные, и на железе остаётся только аккуратно повторить
провода.

Особенности симулятора:
- сеть `Wokwi-GUEST` и публичный брокер **не приватные**: там только
  тестовые токены-заглушки, никаких настоящих паролей;
- зуммер в Wokwi пассивный и может молчать: на настоящем модуле он
  будет пищать;
- если «PUMP» в симуляторе горит наоборот, это особенность модели реле
  в Wokwi: на настоящем модуле смотри раздел 4.

## 1. Сеть и брокер (в FabLab)

1. Включи на телефоне точку доступа, например `XZT-LAB` с паролем.
   Подключи к ней ноутбук.
2. Узнай IP ноутбука: `ipconfig` → строка **IPv4-адрес**
   (например `192.168.43.100`).
3. Запусти брокер из папки `hardware\gateway`:
   ```
   "C:\Program Files\mosquitto\mosquitto.exe" -c mosquitto-day1.conf -v
   ```
   Если Windows спросит про брандмауэр, разреши доступ для **частной**
   сети. Окно не закрывай.

## 2. Первая плата: датчик

**Сначала без проводов.** В `firmware/xzt_node/xzt_node.ino` оставь
`#define ROLE ROLE_SENSOR`, впиши `WIFI_SSID`, `WIFI_PASS` и
`BROKER_IP` (IP ноутбука). Плата: **ESP32 Dev Module**. Загрузи скетч и
открой *Монитор порта* на скорости **115200**. Должно появиться:

```
esp32_sensor  firmware MD5 = 3f2a...     <- отпечаток прошивки
Wi-Fi.... ok, IP 192.168.43.57
MQTT... ok
```

Если плата не прошивается: зажми кнопку **BOOT** на плате, когда в IDE
появится `Connecting...`.

**Подключение датчика DS18B20 и кнопок:**

| Деталь | Вывод детали | Куда на ESP32 |
|---|---|---|
| DS18B20 | VCC (красный) | 3V3 |
| DS18B20 | GND (чёрный) | GND |
| DS18B20 | DATA (жёлтый) | GPIO 4 |
| Резистор 4.7 кОм | между DATA и 3V3 | нужен для щупа; на модуле DS18B20 он обычно уже есть |
| Кнопка A «насос ВКЛ» | одна нога | GPIO 18, вторая нога в GND |
| Кнопка B «насос ВЫКЛ» | одна нога | GPIO 19, вторая нога в GND |

Резисторы к кнопкам не нужны: включена внутренняя подтяжка.

## 2b. Выводы для ESP8266 (NodeMCU)

Скетч сам выбирает выводы по плате. На NodeMCU подписи на плате: D1, D2...

| Плата | Деталь | Вывод NodeMCU |
|---|---|---|
| Датчик | DS18B20 DATA (жёлтый провод / S на переходнике) | **D2** |
| Датчик | DS18B20 VCC / GND | **3V3** / **G** |
| Датчик | кнопка A / кнопка B (вторая нога на G) | **D5** / **D6** |
| Насос | реле IN | **D1** |
| Насос | реле VCC / GND | **VIN** (5 В от USB) / **G** |
| Насос | зелёный / жёлтый / красный (через резистор, катод на G) | **D5** / **D6** / **D7** |
| Насос | зуммер I/O (или S), VCC на 3V3, GND на G | **D2** |
| Хакер | кнопки A, B, C, D, E (вторая нога на G) | **D1, D2, D5, D6, D7** |

D3, D4, D8 не используем: от них зависит, загрузится ли плата.
NodeMCU широкая: ставь её **поперёк стыка двух макеток**, тогда с обеих
сторон остаются свободные ряды.

**Реле:** если оно включается только когда IN = LOW (большинство синих
модулей без перемычки; проверка: подай на IN провод от G, щёлкнуло = LOW),
поставь в скетче `RELAY_ACTIVE_LOW = true`.
**Зуммер** пищит и активный, и пассивный (скетч использует tone).
Если пищит постоянно, поставь `BUZZER_ACTIVE_LOW = true`.

## 3. Шлюз и запись прошивок

В новом окне терминала, в папке `hardware\gateway`:

```
python gateway.py --broker 127.0.0.1 --enroll
```

Нажми на датчике кнопку A. В окне шлюза появится:

```
[enroll] esp32_sensor: recorded firmware 3f2a... -> enrolled_firmware.yaml
... esp32_sensor  ALLOW  trust=0.74 ...
```

Останови шлюз (`Ctrl+C`) и запусти уже **без** `--enroll`:

```
python gateway.py --broker 127.0.0.1
```

Теперь шлюз пропускает только эту прошивку. Любая другая прошивка с
тем же токеном уйдёт в карантин.

## 4. Вторая плата: насос и светодиоды

Роль `#define ROLE ROLE_ACTUATOR`, остальные настройки те же.

**Перед подключением:** на модуле реле поставь перемычку **H** (High
trigger). Тогда в скетче оставь `RELAY_ACTIVE_LOW = false`.

| Деталь | Вывод | Куда |
|---|---|---|
| Модуль реле | VCC (или DC+) | 5V / VIN на ESP32 (5 В от USB) |
| Модуль реле | GND (или DC−) | GND |
| Модуль реле | IN | GPIO 23 |
| Зелёный светодиод | длинная нога через 220 Ом | GPIO 25, короткая в GND |
| Жёлтый светодиод | длинная нога через 220 Ом | GPIO 26, короткая в GND |
| Красный светодиод | длинная нога через 220 Ом | GPIO 27, короткая в GND |
| Модуль зуммера (3 вывода) | VCC | 3V3 |
| Модуль зуммера | GND | GND |
| Модуль зуммера | I/O (или S) | GPIO 14 |

**Насос** подключается к реле, а не к ESP32, и питается от **своего**
источника 5 В:

```
 (+) отдельного 5 В ──> COM реле
                        NO  реле ──> (+) насоса
 (−) отдельного 5 В ──────────────> (−) насоса
 диод 1N4007 параллельно насосу: полоска к (+) насоса, другая сторона к (−)
```

⚠️ **Только низкое напряжение.** Реле умеет переключать 220 В, но на
этом стенде к нему подключается только 5 В. На первый раз вместо насоса
можно поставить вентилятор 5 В или светодиод с резистором.

Если реле работает наоборот (насос включён, когда должен быть
выключен), поменяй в скетче `RELAY_ACTIVE_LOW` на `true`. Если зуммер
пищит постоянно, поменяй `BUZZER_ACTIVE_LOW` на `true`.

**Проверка:** нажимаешь кнопку A на датчике → шлюз пишет `ALLOW` →
загорается зелёный → щёлкает реле → насос работает.

## 5. Третья плата: «хакер»

Роль `#define ROLE ROLE_ATTACKER`. Пять кнопок: GPIO 18, 19, 32, 33, 13,
каждая второй ногой в GND. Для сценария E впиши в
`SENSOR_FW_MD5_COPY` отпечаток датчика из строки `[enroll]`.

**Атаки проводим только в сети стенда.**

Порядок для демонстрации (C делай последней: она блокирует датчик до
перезапуска шлюза):

| Кнопка | Что делает | Что должен сделать шлюз |
|---|---|---|
| A | имя датчика, неправильный токен | 🔴 DENY: аутентификация не пройдена |
| B | незарегистрированное устройство | 🔴 DENY: аутентификация не пройдена |
| E | идеальная подделка датчика + флуд из 60 запросов | первые несколько проходят, затем 🔴 DENY из-за аномальной частоты |
| D | команда насосу **в обход шлюза** | с `mosquitto-day1.conf` **срабатывает** (это и есть дыра); с `mosquitto-acl.conf` брокер её не пропускает |
| C | украденный токен, но чужая прошивка | 🔴 QUARANTINE, зуммер; датчик заблокирован до перезапуска шлюза |

После E подожди 10 секунд, прежде чем снова нажимать кнопки датчика:
частота считается по окну в 10 секунд.

Ночной доступ: перезапусти шлюз с `--demo-hour 3` и нажми кнопку на
датчике. Доверие упадёт, и в объяснении будет видна аномалия.

## 6. Закрываем дыру из сценария D (когда всё остальное работает)

Создай пароли (в папке `hardware\gateway`):

```
"C:\Program Files\mosquitto\mosquitto_passwd.exe" -c passwords.txt xzt-gateway
"C:\Program Files\mosquitto\mosquitto_passwd.exe" passwords.txt esp32_sensor
"C:\Program Files\mosquitto\mosquitto_passwd.exe" passwords.txt esp32_actuator
"C:\Program Files\mosquitto\mosquitto_passwd.exe" passwords.txt esp32_attacker
```

Запусти брокер с `mosquitto-acl.conf`, шлюз с
`--user xzt-gateway --password ...`, а в каждом скетче впиши
`MQTT_USER` (имя устройства) и `MQTT_PASS`. Теперь публиковать в
`xzt/cmd/pump` может только шлюз, а устройства только под своим именем.
Сценарий D перестанет работать, а A, C и E будут отсечены уже брокером, потому что «хакер» не может публиковать от имени датчика.
Это два слоя защиты.

⚠️ Этот режим ещё не проверен на настоящем Mosquitto: в среде, где я
писал код, его нет. Если брокер не запустится, пришли его вывод.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Плата не видна в списке портов | кабель с передачей данных, драйвер CP210x/CH340 |
| `Connecting......` и ошибка при прошивке | зажать BOOT во время загрузки |
| `Wi-Fi....` бесконечно | ESP32 работает только на **2.4 ГГц**: включи на телефоне режим 2.4 ГГц |
| `MQTT... failed rc=-2` | неверный `BROKER_IP`, брокер не запущен или брандмауэр Windows |
| Легальный датчик сразу уходит в QUARANTINE | его прошивка не записана: перезапусти шлюз с `--enroll` и нажми кнопку ещё раз |
| Легальный запрос получает DENY | проверь токен в скетче и в `devices.yaml`; не включён ли `--demo-hour` |
| Датчик всё время в QUARANTINE | после сценария C перезапусти шлюз |
| Температура `-127` | DS18B20 не подключён или нет резистора 4.7 кОм |

## Что честно сказать на защите

- **Отпечаток прошивки сообщает само устройство.** Честная прошивка его
  не подделает, но атакующий со своей прошивкой может отправить любую
  строку (сценарий E). Настоящая проверка требует secure boot или
  подписанного ответа на запрос шлюза.
- **ML-модель в этой версии не используется.** Следующий шаг: шлюз
  захватывает трафик через `tshark`, извлекает те же поля, что в
  Edge-IIoTset, и передаёт их модели. Тогда можно измерить, как модель,
  обученная на датасете, работает на живом трафике.
- **Аутентификация проверяется до расчёта доверия.** Тесты показали, что
  иначе запрос с неверным токеном проходит: взвешенная сумма остальных
  атрибутов перевешивает. В симуляции (Track 2) такой проверки нет,
  и это записано в `HANDOFF.md` как ограничение.
